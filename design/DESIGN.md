# Design Context

> 本文件由 impeccable 技能要求维护，记录本项目的设计上下文与原则。新增界面或改版前先读这里。

**产品名：PigDrop（中文名仍叫猪猪速递）**
一句话：电视端开机即成为一个局域网接收站，屏幕显示二维码；手机扫码打开网页直接上传，手机不装任何 App。

> 命名变更：对外显示名统一成 `PigDrop`（应用桌面名、界面品牌、手机页标题、下载目录 `Download/PigDrop/`），
> 中文名「猪猪速递」保留作为中文别名，不再出现在界面上。本文档下方保留设计期的原始称呼，便于对照当时的决策。


## Design Context

### Users

两类用户，同一个房间里：

**电视端（接收方）** — 坐在沙发上，距屏幕 2.5–3.5 米，手里只有遥控器（方向键 + OK + 返回）。可能在看电视的过程中顺手传个文件，注意力是分散的，不会盯着屏幕研究。他们不能打字、不能悬停、不能滚动页面。这一端的目标是：**让人一眼看懂"现在用手机扫码就行"，并且永远知道焦点在哪。**

**手机端（发送方）** — 站着或坐着，单手拇指操作，竖屏。他们刚用相机扫完码，期待的是一个"立刻能选文件"的页面，而不是一个需要学习的应用。这一端的目标是：**扫码后 3 秒内开始传文件。**

典型任务：把手机里的视频投到电视上看、把照片发到电视给家人看、传一个 APK 到电视安装、把下载好的电影放到电视上。

### Brand Personality

**名字俏皮，界面克制。**

"猪猪速递"是个口语化、带点笨拙可爱的名字，它承担全部的亲和力；界面本身保持安静——像家里的路由器或电灯开关，存在感低，但永远在工作。

这是刻意的不对称：如果界面也跟着卖萌（卡通吉祥物、弹跳动效、彩色气泡），名字的可爱会立刻变成油腻。**俏皮只存在于名字和那一个标记里，其余部分一律克制。**

反参考：不要像商业应用市场（广告位、推荐流、红点提示），不要像投屏软件（各种会员引导、清晰度选择），不要有任何"增值服务"的痕迹。

品牌表达的具体约束：

- 唯一的品牌符号是**线性猪头标记**，不出现卡通吉祥物、拟人化动作、表情包或音效。
- 标记用 `currentColor` 描边，跟随各主题的 `--accent`，不引入第五种颜色。
- 文案保持平实：短句、说人话，不用感叹号，不用"哦/啦/呀"这类语气词。名字已经够轻了，文案再加轻浮就撑不住"可靠"。

### 标记（Mark）

24×24 viewBox，1.5 描边，圆角端点：

| 部件 | 几何 |
|---|---|
| 头 | `circle(12, 14, r=7)` |
| 鼻 | `ellipse(12, 16, rx=3.3, ry=2.4)`，鼻下两点为鼻孔 |
| 耳 | 从圆周 `(6.9, 9.4)` 与 `(9.9, 7.1)` 起笔，二次贝塞尔向外翻出圆角外缘，左右镜像 |

判定依据：试过尖高三耳、直线三角耳、圆角软耳三种，圆角软耳在 22px 下最不容易被读成猫耳或熊耳——尖耳会强烈指向猫科。

尺寸规则：
- **22px（电视页头）/ 15px（手机页头）**：不画眼睛。这个尺寸下眼睛会糊成两个黑点。
- **76px（空状态插画）**：加两个眼睛点，成为有表情的脸。空状态是这个产品唯一露出性格的地方。
- 标签页图标：同一标记置于圆角深底上，强调色 `#3ddcae`，内联为 data URI 以保持单文件。

### Aesthetic Direction

四套完全平行的主题，共享同一套语义 token，但**换掉的不只是颜色**：

| 主题 | 定位 | 字体策略 | 形态语言 |
|---|---|---|---|
| 夜航 noir | 默认。暗色影院感 | Bebas Neue 拉丁 + Noto Sans SC；宽字距 | 6px 圆角，细描边，焦点带发光 |
| 素纸 paper | 客厅家具感，白天不刺眼 | Fraunces 衬线 + Noto Serif SC；负字距 | 14–22px 圆角，硬阴影，暖赭强调 |
| 网格 grid | 瑞士式，信息密度优先 | Archivo Black + Noto Sans SC 900 | 0 圆角，1px 实黑线，纯红强调 |
| 终端 term | 复古传输终端 | 全 IBM Plex Mono | 0 圆角，荧光绿，扫描线纹理 |

主题切换同时改变：字体族、字重、字距、圆角、描边粗细、阴影语言、焦点环样式。这是刻意设计——**如果换主题只是变色，那就不叫主题。**

关键约束：`--qr-bg` 在四套主题里始终是高亮度值。二维码必须衬浅底，反色绘制的码在多数手机相机上识别率明显下降。这是可用性约束，优先级高于"主题一致性"。

### Design Principles

1. **两端独立排版，不做一套响应式。** 电视是 16:9 横屏 + 遥控器，手机是竖屏 + 拇指。它们共享状态和 token，但布局、字号、焦点模型各自实现。把电视端塞进媒体查询断点里，两边体验都会将就。

2. **焦点是电视端唯一的导航语言。** 没有 hover，没有滚动提示。所有可操作元素共用一套焦点环——整行用 `--focus-sh`，行内小按钮用紧凑的 `--focus-sh-sm`（否则 32px 外发光会被列表的 overflow 裁掉），且**焦点永远不能走到看不见的地方**。焦点移动按显式导航图（视觉顺序）执行，不用几何最近邻——后者在纵向堆叠的按钮之间会跳错、会卡死。

3. **文件名保持字面大小写。** 任何 `text-transform` 都不得作用于文件名、扩展名、路径、IP、端口。用户必须看到准确的字面值。同理，所有数字用 `tabular-nums`，进度跳动时不抖宽。

4. **信息层不用大写装饰。** 章节标题、按钮文案可以用 label 样式（大写 + 字距）做视觉分层，但正文和文件名不行。

5. **空状态要给出下一步，不要只说"没有数据"。** 电视端空列表必须同时给出二维码位置提示；手机端空队列要说明文件会保留在电视上。

6. **不做假进度。** 传输进度用真实的分片回传值（原型里是缓动模拟，但接口契约是 `XMLHttpRequest.upload.onprogress`），不用无限循环的加载指示器。

7. **品牌只由一个标记承担。** 猪头标记是所有界面上唯一的品牌符号，靠 `currentColor` 跟着主题走。名字的俏皮不向外扩散——不加吉祥物、不加拟人化动效、不改文案语气。想把品牌做得更"有人味"时，先怀疑这是不是在削弱"可靠"。

8. **不可逆操作必须有二次确认，且默认焦点在「取消」。** 遥控器只有四个方向键和一个 OK 键，误触概率远高于鼠标。删除文件这类操作：确认框弹出时焦点落在"取消"而不是"删除"，返回键等同取消，危险按钮用 `--danger` 填充以示区别。**没有一个删除入口可以一键完成。**

### 行与行内操作（交互模型）

已接收列表的每一行列序固定为：**类型图标 · 文件名 · 大小 · 打开 · 删除**。体积靠右紧跟操作，扫一眼就能判断"要不要删"；打开与删除常驻行内，不藏进二级菜单。

体积列给固定宽度（`58px`）而不是 `auto`：每行是独立 grid，`auto` 列宽不跨行共享，行内文字一变，整列就会各走各的，纵向对不齐。数字用等宽字体 + `font-variant-numeric:tabular-nums` **右对齐**——右边缘齐平，量级（MB/GB）能一眼竖着扫下来；左边缘随位数变化是正常的，不该强行左对齐。

| 焦点位 | 行为 |
|---|---|
| 整行（`f-<id>`） | OK = 打开；悬停/焦点时整行提亮 |
| `打开`（`o-<id>`） | 打开该文件；所属行亮起左侧竖条，提示"正在操作哪一行" |
| `删除`（`x-<id>`） | 弹确认框，默认焦点在「取消」 |

导航：行内 `←` 出列表到左列按钮，`→` 进「打开」再进「删除」；`↑↓` 在**同一列**里换行，所以"删第 5 个"和"打开第 5 个"的按键次数都可预期；末行的 `↓` 显式封底为 `null`，不靠几何回退乱跳。

两个非显然的决定：

- **删除不做成一键。** 行内删除按钮平时压成次要灰（`--ink-3`），只有焦点/悬停才露出 `--danger`——整列红字会让人不敢看这个列表，但按下时必须有危险信号。按下去后仍然过一次确认框，默认焦点在取消。
- **「打开」不是在本应用里渲染，而是交接。** Android TV 上打开文件是把 Uri 交给系统播放器 / 相册 / 安装器，本应用退到后台。所以全屏浮层如实交代交接对象（"正在交给系统播放器打开"），APK 补一句"电视上还需要再点一次安装确认"，而没有可用应用时给的是可执行的下一步（先删除腾空间 / 去文件管理），不是一句"打开失败"。

### 管理已接收文件（交互模型）

入口是列表头右侧的「管理」按钮（列表为空时隐藏）。进入后：

| 状态 | 行为 |
|---|---|
| 行左侧 | 类型图标换成勾选框——管理模式下勾选框是唯一操作语言，图标让位 |
| 行内按钮 | 隐藏。批量场景下每行再挂两个按钮只会让勾选框更难对准 |
| OK | 切换该行选中 / 取消选中 |
| 页头右侧 | `已选 n 个 · 体积`，取代原来的总数 |
| 底部 | 按键提示替换为操作条：`全选` / `删除 n 个` / `完成`；未选中时删除按钮禁用并从导航中跳过 |
| 返回键 / 完成 | 退出管理模式，选择集清空 |

两个非显然的决定：

- **右键 = 跳到操作条。** 遥控器没有长按和快捷键。若只能"下键走到列表末尾再下一格"，删除一个位于长列表中间的选中项要按十几次。所以管理模式把右键定义为跳到操作条；操作条左键回到来源行（`state.lastRow`），不会丢掉位置。
- **删除只在确认后执行，且确认后退出管理模式。** 选择集随删除一起消费掉，不保留"删完还能接着删"的状态——避免用户以为选择还在。

单文件删除在行内完成（见上），打开浮层里另有一个删除入口；三个入口（行内 / 浮层 / 批量）走的是同一个确认框，文案随数量变化。清空全部记录同样并入确认框，按钮改为「全部删除」。

## 落地到 Android TV 的技术约定

设计期这里写过一版「待定」，真做出来之后按实际实现更正（原稿里的 `multipart`、分片续传、SAF 授权、SSE 都没有采用，理由写在各条下面）：

- HTTP 服务：`NanoHTTPD 2.3.1`（约 60KB，无依赖），监听 `0.0.0.0:8080`，端口被占自动往后试 12 个
- 二维码：`ZXing` core 3.5.3，纠错级别 M，内容为 `http://<局域网IP>:8080`
- 局域网 IP：遍历 `NetworkInterface`，按 wlan → eth → 其他排序，跳过回环和 169.254 自分配地址（`ConnectivityManager` 在电视上常把 VPN/虚拟网卡排前面）
- 手机端页面：`assets/www/index.html` 单个 HTML，`PhonePage` 注入品牌/地址/CSS/最近文件后返回，配色由 `Palette` 生成——和电视端同一份色值
- 上传接口：**`PUT /upload?name=<文件名>` + 裸二进制 body**
  - 不用 `multipart/form-data`：浏览器要发 multipart 必须先把整个文件塞进 FormData，大文件双份占内存
  - 不做分片续传：电视侧边收边写、不落临时文件，一次一个文件一条进度，比续传更好用
  - 进度：手机端 `xhr.upload.onprogress`；电视端由服务端每 120ms 回调一次，显示在列表上方的横幅里（不用 Toast，电视上的 Toast 会压在列表上且看不清）
- 存储三档降级：`MediaStore.Downloads` + `IS_PENDING`（API 29+，避免半截文件被媒体库索引）→ 公共下载目录（API 23–28，需 `WRITE_EXTERNAL_STORAGE`）→ 应用私有目录（权限被拒也还能用，界面上如实说文件在哪儿）
- 文件交接：`FileProvider` 把 `content://` / `file://` 统一转成可授权 Uri 交给系统播放器/安装器

### 对比度：原型值在电视上不够

原型按桌面距离定的 `--ink-3`（次要信息：时间行、底部按键提示），在 3 米外看 1080p 时实测不合格：

| 主题 | 原型值 | 实测最低对比度 | 调整为 | 调整后 |
|---|---|---|---|---|
| 夜航 | `oklch(60% 0.02 250)` | 3.73:1（压在聚焦行底色上） | `oklch(65.42% 0.0227 248.17)` | 4.66:1 |
| 素纸 | `oklch(60% 0.022 62)` | 3.16:1（压在暖米 bg-2 上） | `oklch(50.89% 0.0181 67.40)` | 4.64:1 |

只动明度，色相和饱和度没碰，所以气质不变。`--ink-2` 及以上的层级都远高于 4.5:1，不需要改。

## 当前原型

`zhuzhu-sudi/index.html` — 单文件，无构建步骤，直接打开即可。
- 方向键遥控电视，Enter 确认，Esc 返回
- 手机端可真实拖入文件（会读取真实文件名和体积），进度为模拟
- 主题持久化在 `localStorage`（键 `zhuzhu-theme`），也可用 `?theme=paper|grid|term` 直接进入
- 应用名在 `index.html` 脚本开头的 `APP_NAME` 常量，改一处即全局生效（页头、电视品牌位、手机页头三处文字都由它驱动）
- 已接收文件的行内操作：文件名后面依次是体积、「打开」「删除」；打开是全屏交接态（含 APK 安装确认、无可用应用两种特例），删除走确认框
- 已接收文件可管理：批量勾选、全选、删除（带确认）、清空全部（带确认）
- 演示数据为 4 条记录，方便直接试管理模式
